# qq_memory_search

## DESCRIPTION
从指定 QQ 群的最新消息开始，向更早的消息分页读取历史记录。

## PROMPT

使用本工具从当前 QQ 群的最新记录开始，向更早的记录分页读取原始聊天历史。
本工具不是关键词搜索器；它只负责按时间顺序向前翻页。你需要自行检查每页结果是否已经包含目标证据。

只有在当前问题缺少必要的群聊上下文时才调用本工具。调用前必须先确定检索目标，例如：
- 查找被回复消息的 message_id；
- 查找当前消息附近的上下文；
- 查找明确指定时间范围内的消息；
- 查找某条相关图片消息的 image_urls。

参数规则：
1. group_index 必须使用当前交互明确提供的 QQ 群号。群号只能是纯数字，不得猜测、替换或尝试访问其他群。
2. 第一次调用时不要传 cursor，或将 cursor 留空。
3. 为减少调用次数，通常将 limit 设为 100；只需要少量近期上下文时可以使用更小的值。limit 必须在 1 到 100 之间。
4. next_cursor 是不透明分页令牌。继续翻页时，必须把上一次返回的 next_cursor 原样作为下一次的 cursor；禁止解析、修改、拼接、自行计算或重复使用旧 cursor。
5. 每次调用都会从 cursor 所在位置继续向更早的记录读取，不会自动包含新追加的消息。
6. 消息整体从最新记录向更早记录翻页；单页内部已经按时间正序排列，第一条最旧，最后一条最新。

返回字段说明：
- count：本页成功返回的消息数量。
- scanned_count：本次检索链从最新记录开始累计向前扫描的记录数量。损坏或无法解析的记录可能计入 scanned_count，但不会计入 count。
- has_more：在系统允许的检索范围内是否还能继续向前读取。
- next_cursor：下一页使用的不透明令牌。为空时必须停止。

每次获得结果后，按照以下顺序判断：

1. 已找到目标 message_id、目标图片 URL 或足以回答问题的上下文：
   立即停止调用并输出相关证据。

2. 用户只需要“最近的聊天内容”或当前消息附近的普通上下文：
   默认只读取一页，然后停止；不得因为 has_more=true 自动继续。

3. 用户指定了时间范围：
   当本页最早一条消息的 datetime 已经早于时间范围下界时，说明时间窗口已经覆盖，立即停止。

4. 返回 has_more=false 或 next_cursor 为空：
   立即停止。

5. scanned_count 已达到系统规定的最大扫描数量：
   无论是否找到目标，都必须停止，并输出“在最近 scanned_count 条记录中未找到明确相关信息”。

只有同时满足以下全部条件时才允许继续调用：
- 当前检索目标尚未找到；
- 当前证据确实不足；
- has_more=true；
- next_cursor 不为空；

禁止仅仅因为 has_more=true 就继续调用。
禁止重复检索已经读取过的 cursor。
禁止根据文件大小、消息数量或其他字段推算 cursor。
禁止为了理解普通文字消息而查找图片 URL。

本工具不能理解图片内容。是否使用其他图片分析工具由上层节点决定，本工具本身不要要求调用 imageread。

完成检索后只输出与当前问题直接相关的消息、发送者、时间、message_id、reply 和必要的 image_urls，不要复述无关记录。
